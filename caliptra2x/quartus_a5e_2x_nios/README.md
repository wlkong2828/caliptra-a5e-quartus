# quartus_a5e_2x_nios/ — Nios V + Caliptra 2.x (full system) on A5EC065BB32AE6S

Quartus Pro 25.3 project for `../rtl_2x/nios_caliptra2x_top.sv`: the same Nios V/m host system as the
Caliptra 1.1 project [`../../quartus_a5e_nios/`](../../quartus_a5e_nios/), driving Caliptra 2.x
(caliptra-rtl v2.1.2, passive / core-only) through `avmm_to_axi`.

> The 2.x design **does not fit** the A5E 065 (Caliptra 2.x alone is ~126 % of the ALMs). This project
> synthesizes (286,415 / 222,400 ALMs, 129 %). `quartus_fit` was OOM-killed at 13.9 GB on a 15 GB host;
> the guide estimates fit needs at least 32 GB, and it would stop on ALM overflow anyway. See `docs/caliptra-2x/NIOS_CALIPTRA_2X_INTEGRATION.md` §14, §17, §18.

| Path | What |
|---|---|
| `qsys/nios_caliptra2x_sys.tcl` | Platform Designer script, derived line-for-line from `quartus_a5e_nios/qsys/nios_caliptra_sys.tcl` (only the Caliptra window differs: 1 MiB `caliptra_axi` at `0x0010_0000`) |
| `qsys/nios_caliptra2x_sys.qsys`, `qsys/ip/`, `qsys/nios_caliptra2x_sys/` | Generated PD system + IP (committed, as in 1.x) |
| `ip/rst_release.ip` | Agilex 5 Reset Release IP (copy of the 1.x one) |
| `nios_caliptra2x_a5e.qpf/.qsf` | Project; `.qsf` generated by `gen_qsf.py` (2.x sources from `../quartus_a5e_2x/caliptra2x_a5e.qsf` + Nios/glue/IP like the 1.x QSF) |
| `nios_caliptra2x.sdc` | Same constraints as `quartus_a5e_nios/nios_caliptra.sdc` |
| `sw/app/main.c` | Nios host firmware, 2.x port of the 1.x `main.c` (same flow and LED/MAGIC codes) |
| `sw/bsp/` | HAL BSP generated with `niosv-bsp` from this PD system (same settings as 1.x) |
| `sw/build_app.sh` | Build the app + `onchip_mem.hex` (xPack `riscv-none-elf-gcc`, CMake, Ninja) |
| `onchip_mem.hex` | Nios program RAM image (64 KiB), from Quartus `elf2hex` |
| `run_nios2x_a5e_docker.sh [syn\|fit]`, `dock.sh` | Docker flow (Tcl → PD → ipgenerate → synthesis [→ fit]) |
| `output_files/*.syn.summary`, `*.flow.rpt`, `flow.log` | Committed synthesis summary / flow report / log |

Build (Linux x86-64, Docker image `alterafpga/quartuspro-v25.3:agilex5`, `LIC_HOST=/path/SW-AGILEX-5E.dat`):

```bash
scripts/fetch_deps.sh                                   # from the repo root, once
cd caliptra2x/quartus_a5e_2x_nios
RISCV_BIN=/path/to/xpack-riscv-none-elf-gcc/bin sw/build_app.sh   # only if main.c changed
QPAR=4 ./run_nios2x_a5e_docker.sh syn                   # ~30 min, ~8 GB RAM
```

MAGIC / LED codes (identical to 1.x): `1` alive, `2` ready_for_fuses, `3` AXI users + timer + WDT
programmed, `4` fuses done, `5` ready_for_mb_processing, `6` FIRMWARE_LOAD issued, `7` mailbox complete,
`0xCA11F00D` runtime (LED `0x0D`); `0xDEAD000E` timeout, `0xDEAD000F` failure, `0xDEAD00FF` fatal retries
exhausted, `0xDEAD0010` re-boot after fatal failed; warm reset `0x13`/`0x14`/`0x15`/`0x17`.
