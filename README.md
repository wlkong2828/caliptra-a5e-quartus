## rtl/ (passive wrapper)

`rtl/caliptra_passive_top.sv` is the thin Caliptra 1.x passive-mode wrapper referenced by the Quartus QSF as `../rtl/caliptra_passive_top.sv` (sibling of `quartus_a5e_nios/`). The full `caliptra-rtl/` tree is **not** in git: get it from release [rtl-20261101](https://github.com/pwilliam282/caliptra-a5e-quartus/releases/tag/rtl-20261101) or `git clone --branch v1.1 https://github.com/chipsalliance/caliptra-rtl.git` into `caliptra-rtl/` at the repo root.

Referenced by the QSF as `../quartus/syn_src/*.sv`:

## Caliptra bootROM (`fw/`)

`fw/caliptra-rom.hex` is the Caliptra **1.x** bootROM (caliptra-sw rom-1.1.1, 6144 x 64-bit words, same image used in sim to reach `ready_for_runtime`); `fw/caliptra-rom.bin` + `fw/SHA256SUMS` for verification.
`quartus_a5e_nios/rtl/nios_caliptra_top.sv` instantiates `caliptra_passive_top #(.ROM_INIT_FILE("../fw/caliptra-rom.hex"))`, which `$readmemh`s it into the Caliptra ROM M20K at synthesis (path is relative to `quartus_a5e_nios/`). The QSF also lists it as `HEX_FILE` for dependency tracking.
**Do not use a Caliptra 2.x ROM** — it is incompatible with this 1.x RTL.

## Fuse controller IP + firmware download (Nios)

The Nios project now runs the full Caliptra 1.x passive boot like a production SoC:
power/reset → `ready_for_fuses` → **`soc_fuse_ctrl`** (SoC fuse-controller soft IP, `quartus_a5e_nios/rtl/soc_fuse_ctrl.sv`)
writes all 83 `FUSE_*` registers from `fw/fuse_image.hex` + `CPTRA_FUSE_WR_DONE` → ROM boots (Nios services `etrng_req`) →
`ready_for_fw_push` → Nios mailbox **FIRMWARE_LOAD** of `fw/caliptra-fw-bundle.hex` (held in `soc_fw_store`, an on-chip
M20K ROM standing in for boot flash) → `ready_for_runtime` → MAGIC `0xCA11F00D`.
Fuse image is generated by `scripts/gen_fuse_image.py` (TEST values only). Details, address map and MAGIC codes:
[`quartus_a5e_nios/README.md`](quartus_a5e_nios/README.md). Sim: `sim/run_nios_top_fw.sh`.
